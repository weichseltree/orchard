# First visits, local setup and public presentation

Reviewed on 2026-09-13 against the working tree based on `850cb46`.
This review records local validation. A Git push or a passing remote check
does not record a deployment; the release review remains separate.

## What changed

- The public page explains the grove through a real particle-tape poster,
  four room entry links, controls and source links. Its hall image is
  explicitly labelled as an architectural render. Image provenance and
  digests are in `grove/public/site/imagery.json`; share metadata and a
  favicon accompany the page.
- `pnpm demo` generates local synthetic media, starts beside a tape, and
  skips production authentication, presence, media and update connections.
  Production builds ignore `?demo`. Optional video encoding failures leave
  the tape usable and remove partial video output.
- A first-visit guide explains the current device's controls, identifies
  the room and links to its open doorways. Buttons stay legible against
  bright walls. Keyboard controls respect focused form controls and dialogs;
  touch controls fit in portrait and landscape. Malformed links and failed
  3D startup have a recovery path.
- Baked rooms no longer call Three.js with an empty list of lights, which
  previously logged an undefined-object error each time a room loaded. A
  loader regression and browser console-error capture cover that path.
- The dashboard retains failed submissions and ruling notes, preserves
  edits typed during a save, guards pending actions, and removes stale
  moderation controls when a refresh fails. Cancellation sends no ruling;
  an invalid ban duration cannot become a permanent ban.
- README, contributor instructions, optional service configuration and
  browser-storage disclosure match the implementation. The Checks workflow
  runs Python, dashboard and grove checks without deploying.

presence availability, or headset performance. Remote CI status is recorded
