Baseline: `062bb1e`, after the first-visit and housekeeping pass. This review
compares that source with the rebuild, using the same room assets and
preserving the existing research and camera-station evidence. The
[measurement guide](../QUALITY.md) gives runnable commands and definitions;
[the metric record](2026-09-13-rebuild-metrics.json) contains the final
before/after numbers.

The full local checks pass: 238 Python tests, 273 grove tests, four browser
measurement-helper tests, TypeScript, production build and size/loading
budgets. Browser audits pass 97/97 demo checks and 47/47 production checks.
Both detect zero automatic axe violations; four demo manual-review findings
remain. Screenshots cover desktop/phone landing, phone guide and the desktop
timing panel.

## What changed

Room loaders and exhibit code arrive when needed. A room starts its hangings
as soon as its own shell is ready, while neighbouring shells continue to
load. In-flight work is shared, shell failures can retry, and a failed live
exhibit lookup uses the scene's saved references. The full doorway/window
neighbourhood remains. A failed or cancelled video attachment releases the
single decoder, and native-only browsers skip the HLS library.

The presence SDK loads when a connection is requested, so the local demo
does not download unused networking code. Connection attempts share pending
work, reject stale callbacks and stop abandoned imports from opening a
socket. Production keeps the same configuration and connection triggers.

New bundles retain exact frame timestamps and original cadence. Frame
thinning no longer makes the phone/Quest variants run twice as fast as the
desktop variant. Known units and source origins reach provenance and labels;
unknown units remain source time. Omitted heat/bond/other channels are named
explicitly. Existing OTC1 chunks and old manifests remain readable. This
does not implement species palettes or transport extra scientific channels.

The public page's skip link now moves keyboard focus into the content. Six
undersized discrete links per tested phone layout now meet the 44-pixel
product target. Guide and recovery text use an opaque background so their
contrast does not depend on the moving world. The timing panel has a name,
keyboard focus, scrolling and bounded dimensions. The hall image is encoded
as lossless WebP: 966,594 to 572,830 bytes, with identical decoded RGBA
pixels. Its source PNG remains in `docs/img/`, its source/encoded hashes and
encoding command in `grove/public/site/imagery.json`. The simulation poster
is unchanged.

The old frame meter received the movement timestep capped at 100 ms. It now
receives raw animation intervals, suspends non-XR hidden-tab frame work and
reports a rolling distribution. Its string report updates twice per second
instead of rebuilding every rendered frame. Build reports measure both the
startup closure and all JavaScript, including the versioned transcoder.
Browser reports add explicit cold/warm accounting, layout and accessibility
checks. All measurement remains local unless someone deliberately shares a
report; the CI workflow stores its own synthetic test reports as artifacts.

## Evidence and tradeoffs

The five-frame synthetic clock fault fixture is
`[10, 10.1, 11.9, 12, 14]`. Reconstructed frame-time error falls from 1.0
source unit to zero; exact timestamp round trips rise from 2/5 to 5/5.
The phone/Quest-to-desktop source-speed ratio falls from 2 to 1. Chunk
payload remains 704 bytes. These compare Python-produced bundles through
the real TypeScript schema/timeline, not DOM text or a scientific result.
Labels also receive large-origin/tiny-cadence regressions so rounding does
not collapse adjacent frames.

Exact time arrays cost additional JSON bytes. Measured from local source
indices: 29,664 bytes for an 801-frame einstruct tape (0.066% of particle
payload), 26,312 for a 1,129-frame spectre tape (0.042%), and 14,435 for a
sparse 801-frame phototroph tape (14.07%). The sparse tape's percentage is
substantial despite the small absolute size. No tolerances are fitted to
hide clock differences. Legacy compatibility checks covered ten existing
bundles, thirty variants and sixty first/last chunks.

Those overhead figures count `times_tau` and `source_dt_tau`; additional
provenance and timing-description fields add a small further manifest cost.

The loading-order witness uses cold Chromium/SwiftShader contexts in local
Vite, with an additional case delaying every unrelated GLB by 350 ms. The
baseline requests tape data only after all eleven room GLBs finish. The
rebuild requests it before the entire neighbourhood finishes. Every scenario
ends with eleven shells, seven tapes, visible transport and no script,
console or external-connection errors. Timings are recorded per run rather
than claimed as device or CDN performance. The first sample and the later
repeat are both retained; the original first-sample harness expected exactly
one completed GLB, which was stricter than the intended ordering guarantee.

The independent three-sample production gzip audit records lower early
transfer, but slower first-room readiness in this software renderer:

| Local browser observation, median of three | Baseline | Rebuild |
| --- | ---: | ---: |
| Landing cold transfer, desktop | 1,040,753 bytes | 647,006 bytes |
| Grove cold transfer, desktop | 12,851,828 bytes | 11,734,250 bytes |
| Grove cold transfer, phone | 12,683,848 bytes | 9,905,353 bytes |
| First room, desktop cold | 941.7 ms | 968.7 ms |
| First room, phone cold | 550.8 ms | 837.5 ms |
| First room, desktop warm | 4,645.8 ms | 5,137.2 ms |
| First room, phone warm | 3,016.4 ms | 3,723.4 ms |

These slower readiness observations are unresolved performance evidence.
They are not replaced by the better first-tape timings. The early transfer
window contains different room counts before/after, so the byte decrease
partly reflects scheduling and is not a whole-palace bandwidth saving.
The metric record retains sample ranges and room counts. Warm visits use
HTTP caching, with service workers off; the local server does not model CDN
Brotli or conditional 304 responses.

Startup-code savings defer work; they do not imply that the full site's
JavaScript or eventual transfer shrank. Added features and chunk boundaries
increase total JavaScript slightly. The architectural image reduction saves
bytes without changing its pixels. All room geometry, texture tiers and
particle payloads remain present. The generic large-chunk warning for
Three.js/HLS remains; import-extension/deprecated-build-option warnings were
fixed without raising warning limits.

## Reproduction and limits

Local source and build snapshots were made before edits, with the baseline
commit in `results/rebuild/baseline-commit.txt`. The baseline production
build was given the same local `public/` inputs, including ignored PNG bake
fallbacks. Its archive has no `.git`, so its built version says `unknown`;
the source commit is recorded separately. A clean CI checkout omits those
optional files and has a smaller whole-build inventory.

Detailed local records live under `results/rebuild/` and `results/quality/`:
build-before/after JSON, loading-pipeline script and both runs, tape-fidelity
before/after JSON, timestamp overhead and legacy compatibility records,
unit-test logs, and browser reports. Earlier failing checks remain there.
The new tests cover the actual faults: delayed shells, decoder cancellation,
irregular clocks, chunk/header mismatch, long foreground stalls and omitted
transcoder accounting. A test count is not a claim of complete coverage.

A combined test run also exposed an older digest test's fixed five-timer
wait: Web Crypto had not finished under concurrent load. The test now waits
for the actual in-flight request to settle before making the same digest
assertions. The failed log is preserved as
`results/rebuild/vitest-digest-wait-failure.log`.

Browser checks use headless Chromium with software rendering and emulated
touch. Automatic accessibility results retain manual-review findings. The
production harness disables service workers and blocks external services;
it cannot establish live auth, presence, media availability, physical Quest
frame rate, native iPhone HLS or scientific exhibit acceptance. Phone
initial transfer under 20 MB and hardware frame targets remain open until
their actual witnesses pass. No site deployment, exhibit ruling, research
rebake or cloud configuration change is part of this rebuild.
